### Task 3: Play metrics and per-play log (NFR-14) — test first

Test file: `src/test/java/com/thilaga/fruitmachine/application/MachineServiceTest.java` (new methods; reuse its existing stubs and `SimpleMeterRegistry`).

a. **`paidPlayIncrementsPlayAndPayoutCounters`**: create a machine, play with a `NO_WIN` spin, then a jackpot or small-prize spin. Assert `fruitmachine.plays` = 1 per play and `fruitmachine.payout.pence` equals the paid amount. Assert the counter for free plays `fruitmachine.freeplays.credited` equals the credit given on a NONE-policy shortfall play (add a second assertion only if the setup is short; otherwise cover it in a separate method).
b. **`freePlayCreditIsCounted`** (only if (a) cannot reach a shortfall cheaply): NONE machine, float 300p, small prize, expect counter = 1 free play? Compute from AC-22: shortfall 100p gives 1 free play. Assert counter = 1.
c. Make it fail first (counter absent), then implement:
   - `MachineService` gets a `MeterRegistry` constructor argument; increments counters after a successful commit-side settlement inside the transaction (counters are in-memory, so a rollback leaving a counted increment is a known edge; note in code comment as `shortcut: counters not rolled back on failed play, upgrade to recording via history query if exact accounting needed`). Preferable simpler alternative: increment after `save` returns without throwing; the rollback risk is only on commit failure after return. Pick this and document.
d. Log line: `log.info("play machine={} play={} prize={} paid={} freePlays={}", ...)` in the same method. Verify by running a Testcontainers test and checking the log in `./mvnw test -Dtest=MachineServiceTest` output, or assert nothing (logging is not an AC). Decision: no log assertion test; verify manually.
e. Verify: `./mvnw test -Dtest=MachineServiceTest` then `curl http://localhost:8080/actuator/metrics/fruitmachine.plays` after a play (with compose up).

Note for the code: `MeterRegistry` is a Micrometer type in `application`, not `domain`. Domain stays pure.

Commit: "Count plays, payouts and free-play credits; log each play (Issue 6)".

## 7. Risks and open points

- **App DB user has DDL rights.** Needed for Flyway at startup. Least privilege is partial; a separate migrator user is the upgrade path. Stated in README.
- **Counters are incremented before commit returns.** If the commit fails after `save`, the counter is ahead of the DB. Shortcut comment in code; acceptable for NFR-14 measurement, not for money accounting (money is checked in the DB, AC-33).
- **Image build time.** Multi-stage build downloads Maven deps each time unless cached. Acceptable for a demo; no BuildKit cache mount added.
- **Docker must run for the smoke test.** Command checks cannot run in CI without Docker-in-Docker; CI keeps `./mvnw verify` only. The compose path is verified manually and recorded in `verification.md` in Issue 7.
- **Body size limit (NFR-17).** Not set beyond framework defaults. Ask before adding a limit if the reviewer expects an explicit number.
